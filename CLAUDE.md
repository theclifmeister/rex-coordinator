# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Claude Code plugin (`.claude-plugin/plugin.json`) that turns one Rex terminal pane into a **coordinator**: it never does the work itself, but hands each task to a fresh worker Claude in its own Rex tab and git worktree, then merges the result into a feature branch. Everything is bash + markdown; there is no build step and no test suite. Runtime deps: `rex`, `git`, `jq`, `bash`.

## Checking changes

- Lint: `shellcheck scripts/*.sh hooks-handlers/session-start.sh` (scripts source `lib.sh`, so use `shellcheck -x` from `scripts/` to follow it).
- Validate JSON: `jq . .claude-plugin/plugin.json hooks/hooks.json`.
- Real testing means installing the plugin and running `/coordinator-start` in a Rex pane of some scratch git repo. Most scripts refuse to run outside the coordinator pane (`require_coordinator`).

## How the pieces fit

- **Activation** — `/coordinator-start` (`skills/coordinator-start/`) runs `scripts/start.sh`, which writes `block=`, `session=`, `feature=` to `<git-common-dir>/rex-coordinator/state`. On every session start / `/clear` / compaction, `hooks/hooks.json` runs `hooks-handlers/session-start.sh`, which emits `additionalContext` telling Claude to load the `rex-coordinator:coordinator` skill — but only when `$REX_BLOCK` matches the recorded block and `CLAUDE_ROLE` is not `worker`. Every other pane stays silent; keep it that way.
- **Playbook** — `skills/coordinator/SKILL.md` is the coordinator's behavior spec (what to run, how to merge, rules). Changes to the flow usually mean editing this file, and keeping it consistent with the scripts it names.
- **Task lifecycle** — `new-task.sh <slug>` (branch + worktree at `.claude/worktrees/<slug>` off the feature branch, brief rendered from `skills/coordinator/brief-template.md` via `sed` placeholder substitution) → coordinator fills `{{TODO}}`s → `launch-worker.sh` (refuses while `{{TODO` remains; `rex run ... env CLAUDE_ROLE=worker claude`, stores block ID in `tasks/<slug>.block`) → worker writes `reports/<slug>-report.md` and `rex send`s `REPORT DONE|BLOCKED <slug>` → coordinator merges `--no-ff` → `finish-task.sh` (refuses unless merged, unless `--abandon`).
- **Side channels** — `research.sh <topic> [--ref <branch|commit>]` opens a read-only worker in its own background tab, in a detached worktree at `.claude/worktrees/_research/<topic>` checked out at the feature branch tip or `--ref` (never the main checkout's working tree; `_` can't start a slug, so no clash with task worktrees). `tasks/research-<topic>.block` holds the tab, `tasks/research-<topic>.ref` holds `<ref> <short sha>` (a commit `--ref` is stored as its short sha; `research_reads` in `lib.sh` renders it as `<branch>@<sha>` or just `<sha>`, for status and the ledger), answer in `research/<topic>.md`, no branch; `finish-task.sh` force-removes the worktree and the ref file. `tell.sh` sends long messages via a file in `messages/` plus one short typed line, because long `rex send` input gets truncated. `watch.sh` is a background fallback that detects a report file (or, for research, a non-empty answer file), a `REPORT DONE|BLOCKED <slug>` marker at the start of a line in a task tab (after optional spaces and Claude Code's `⏺`, so a brief on screen can't trigger it), or a dead tab. It never scans a research tab's text: the typed instruction already contains `RESEARCH DONE <topic>`.
- **Board (tsk, optional)** — `new-task.sh <slug> [T<n>] [--title ...]` links (or creates — then `--title` is required, checked before any branch exists) a tsk task and writes `tasks/<slug>.tsk` (`<uuid> T<n>`); its title/notes/steps go into the brief by `jq`/`awk`, never `sed` (notes hold `|&/` and newlines). `launch-worker.sh` → `started --no-dispatch` + one guarded notes line; `finish-task.sh` merged → `review --on you` and the link moves to `review/<slug>.tsk` (only if the task really is in review); `--abandon` → note + `done`, link removed. `board.sh` does blocked/unblock/show by slug. `watch.sh` also exits on `BOARD REPLY`; `board-watch.sh` polls `review/*.tsk` (45 s) for `BOARD SENT BACK|DONE|MOVED`, records `seen=` in the link so each event fires once, and drops the link on done. `new-task.sh` linking a task again removes its `review/` link.
- **Memory** — `finish-task.sh` appends one line per closed task to `history.md` (date, slug, merged/abandoned/research, sha (research: `<branch>@<sha>` or `<sha>`), board T-number if linked, the report's `Summary:` line, paths relative to the state dir — older lines hold absolute paths, and both must keep working); `session-start.sh` puts the last 15 lines in the coordinator's context and names the state dir; `scripts/recall.sh <word>...` searches the ledger, briefs, reports and research answers.
- **Shared helpers** — `scripts/lib.sh` (`set -euo pipefail`, `die`, `state_dir`, `state_get`, `repo_root`, `require_coordinator`, `check_slug`; board: `have_tsk`, `tsk_try` (warns, never fails; exit in `$TSK_RC`, exit 3 = indeterminate), `tsk_task`, `tsk_link`, `tsk_link_file`, `one_line`, `canon_dir`; `research_reads`). `repo_root` is derived from the git common dir so scripts work from inside a worktree too.

## Conventions and invariants

- State lives only in `<git-common-dir>/rex-coordinator/` (never committed, shared across worktrees); `start.sh` adds `.claude/worktrees/` to `.git/info/exclude` rather than `.gitignore`.
- `CLAUDE_ROLE=worker` is the guard that stops workers from coordinating; every entry point checks it.
- Board writes: only the coordinator (its scripts, or commands named in the playbook) changes a board task's status, notes, base or replies. Workers may only `tsk steps <uuid> add|toggle` on their own task (the brief says so). Every board call is best-effort (`tsk_try`) and skipped without `tsk`; a tsk failure never fails git/Rex work. Always `-p "$root"` (absolute) on project-scoped calls and address tasks by UUID — a worktree is a different tsk project. Always `started --no-dispatch`. `done` is set only by `finish-task.sh --abandon`. Guard non-idempotent writes (`--append-notes`, `reply`, `steps toggle`) by reading first.
- Never test against the real board: tsk has one global store (`~/.tsk/tsk.json`); run tests through a wrapper that sets `HOME` to a throwaway dir.
- The message protocol strings (`REPORT DONE`, `REPORT BLOCKED`, `RESEARCH DONE`, `ACK <slug>-<n>`, `BOARD REPLY|SENT BACK|DONE|MOVED|IDLE`, and the report's first line `Summary: <one line>`) are matched across the brief template, `research.sh`, `tell.sh`, `watch.sh`, `finish-task.sh` and the playbook — change them everywhere at once.
- Brief template placeholders (`{{SLUG}}`, `{{WORKTREE}}`, `{{FEATURE}}`, `{{COORDINATOR_BLOCK}}`, `{{REPORT}}`, `{{TSK_NUM}}`, `{{TSK_ID}}`, `{{BOARD_TASK}}`) are filled by `new-task.sh`; lines between `<!-- board -->` and `<!-- /board -->` are dropped when no board task is linked; `{{TODO...}}` is left for the coordinator.
- Slugs must match `^[a-z0-9][a-z0-9._-]*$` (they become branch names and file names). Task slugs may not start with `research-`: `tasks/research-<topic>.*` belongs to research.
- Skills reference scripts via `${CLAUDE_PLUGIN_ROOT}`; bump `version` in `plugin.json` when releasing.
